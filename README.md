# كفاءات — النموذج التعليمي المصغّر

واجهة عربية RTL مستوحاة من الشعار المرفق: الأزرق #07577B والذهبي #9C802C والأبيض. الألوان تقديرية من الصورة، وليست دليلاً رسمياً للهوية. الشعار الأصلي محفوظ كما هو؛ يعرض الشريط الجانبي الجزء الرئيسي منه دون إعادة رسم.

## ما الذي يعمل؟

- مقرر ثابت واحد: «مقدمة في المهارات الرقمية»؛ عنوان تجريبي قابل للتغيير.
- تبديل مباشر بين الطالب والمعلّم والمشرف دون حسابات أو مصادقة.
- المعلّم ينشئ وينشر واجباً من 1–20 سؤالاً. أربعة خيارات وإجابة صحيحة واحدة لكل سؤال.
- الطالب يجيب؛ الخادم يحسب الدرجة ويحفظ محاولة مجهولة.
- المشرف يرى عدد المحاولات ومتوسط نسب النتائج وآخر 50 محاولة.
- لا رفع ملفات، ولا أسماء، ولا بريد إلكتروني، ولا إدارة مقررات.
- لا تعديل أو حذف واجب منشور في هذه النسخة. لا مواعيد نهائية ولا منع إعادة المحاولة.

## مهم قبل الاستخدام

هذه **نسخة تجريبية وليست نظام اختبارات آمن**. اختيار الدور ليس مصادقة، ويمكن لأي زائر اختيار المعلّم أو المشرف. يفحص الخادم الدور المرسل والإجابات وحجم الطلب، لكن لا يمكنه إثبات هوية الشخص أو منعه من انتحال دور آخر. لذلك تغير شرط الصلاحيات الأصلي: أصبحت الفحوص قواعد لتجربة الأدوار وليست عزلاً أمنياً.

استخدم بيانات مصطنعة فقط، ولا تدخل أسماء الطلاب أو درجات فعلية أو معلومات شخصية في العناوين والأسئلة. كل محاولة جديدة مستقلة. يستطيع أي زائر الإنشاء وإعادة التسليم، وقد يرفع ذلك استهلاك قاعدة البيانات. لا يوجد تحديد معدل موزّع أو مكافحة إساءة استخدام في هذا النموذج؛ لا تفتحه لجمهور حقيقي. أضف المصادقة وتقييد المعدل قبل ذلك.

## التوتريال: من فك الضغط إلى النشر

### 1. التجربة على جهازك أولاً

1. ثبّت Node.js إصدار 24 LTS وVS Code. إذا كان Node مثبتاً، افتح Terminal ونفّذ `node --version` للتحقق من الإصدار.
2. فك ضغط الحزمة وافتح مجلد `kafaat-mini` في VS Code، وليس الملف المضغوط نفسه.
3. من Terminal داخل المجلد نفّذ، كل أمر على حدة:

```bash
npm ci
npm test
npm run build
npm run dev
```

4. افتح [النموذج المحلي](http://localhost:3000).
5. سيظهر واجب تجريبي من ثلاثة أسئلة. لا تحتاج إلى Neon لهذه التجربة.

**الحفظ المحلي مؤقت داخل ذاكرة الخادم**، وليس داخل المتصفح. تحديث الصفحة يحتفظ بالبيانات ما دام الخادم يعمل، لكن إيقافه يمسح الواجبات والمحاولات المحلية. لإيقافه اضغط Ctrl+C في Terminal. لا تفتح `index.html` بالنقر المزدوج، لأن وظائفه تحتاج إلى الخادم.

### 2. جرّب دورة العمل كاملة

1. اختر «معلّم» ثم «إنشاء واجب».
2. اكتب عنواناً تجريبياً، ثم السؤال وأربعة خيارات مختلفة وحدّد الصحيح.
3. أضف سؤالاً آخر إذا رغبت، ثم اضغط «حفظ ونشر الواجب».
4. اختر «طالب»، وافتح الواجب الجديد، وأجب ثم اضغط «تسليم وعرض النتيجة».
5. اختر «مشرف»: ستجد المحاولة ودرجتها. زر «تحديث» يجلب أحدث البيانات.

الدرجة = عدد الإجابات الصحيحة؛ لكل سؤال درجة واحدة. المتوسط في لوحة المشرف هو متوسط **النسب المئوية للمحاولات**، وليس عدد الطلاب أو متوسط درجات طلاب فريدين. يمكنك تجربة الواجب أكثر من مرة.

### 3. إنشاء Neon Postgres للحفظ الدائم

1. افتح [Neon](https://console.neon.tech/) وأنشئ مشروعاً تجريبياً جديداً، مثلاً `kafaat-mini`.
2. افتح SQL Editor في قاعدة البيانات الجديدة. انسخ محتوى `db/schema.sql` كاملاً وشغّله. ستنشأ جداول `quizzes` و`attempts` وواجب تجريبي.
3. من نافذة Connect انسخ Connection string كاملاً. لا ترسله في المحادثة ولا تضعه في GitHub.
4. أنشئ ملفاً باسم `.env.local` في جذر المشروع اعتماداً على `.env.example`، وضع فيه:

```dotenv
DATABASE_URL=ضع_رابط_الاتصال_الكامل_هنا
DEMO_MODE=true
```

5. أوقف الخادم المحلي وأعد تشغيل `npm run dev`. يجب أن يظهر في التذييل «الحفظ متصل بـ Neon».
6. أنشئ واجباً وسلّمه، ثم أوقف الخادم وشغّله؛ يجب بقاء البيانات.

لا تنتقل المحاولات المؤقتة القديمة تلقائياً إلى Neon. إعادة تشغيل SQL آمنة بالنسبة للواجب التجريبي، ولا تمسح الجداول. لا تستخدم قاعدة تحتوي بيانات حقيقية.

### 4. رفع المصدر إلى GitHub

1. أنشئ مستودعاً جديداً **خاصاً** باسم `kafaat-mini` في [GitHub](https://github.com/new). اتركه فارغاً دون README أولي.
2. ثبّت Git إذا لم يكن متاحاً. من Terminal داخل المشروع نفّذ:

```bash
git init
git add .
git status
```

3. راجع القائمة قبل المتابعة: يجب ألا يظهر `.env.local` أو `node_modules`. ملف `.gitignore` يستثنيهما. إذا ظهر سر، توقف وأزله من الملفات المجهزة للرفع، وغيّر السر إذا انكشف.
4. أكمل الأوامر، مع استبدال `YOUR_USERNAME` باسم حسابك:

```bash
git commit -m "Initial Kafaat demo"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/kafaat-mini.git
git push -u origin main
```

قد يطلب Git تسجيل الدخول؛ استخدم تدفق GitHub الرسمي ولا تشارك رموز الوصول هنا. لم تُرفع الحزمة تلقائياً إلى حسابك.

### 5. النشر على Vercel

1. افتح [Vercel](https://vercel.com/new)، ثم استورد مستودع GitHub.
2. الإطار: **Other**، وجذر المشروع هو المجلد الذي يحتوي `package.json`.
3. الإعدادات موجودة في `vercel.json`: أمر البناء `npm run build`، ومجلد الواجهة `public`. تُنشر `api/app.js` كدالة Node.js بجانب الواجهة. اختر Node.js 24.x إذا ظهر اختيار الإصدار.
4. قبل النشر أضف متغيري البيئة في Vercel:

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | رابط Neon الكامل |
| `DEMO_MODE` | `true` |

5. اختر البيئات التي ستجرب فيها؛ اجعل Preview متصلاً بقاعدة تجريبية مستقلة إذا أردت عدم خلط المحاولات مع Production.
6. اضغط Deploy. افتح الرابط بعد النجاح وجرّب الدورة: إنشاء ← حل ← نتيجة ← لوحة المشرف.
7. أي تعديل لاحق لمتغيرات البيئة يتطلب إعادة نشر. كل دفع إلى فرع الإنتاج يمكن أن يشغّل نشراً جديداً عبر تكامل GitHub.

النموذج يرفض التشغيل على Vercel دون `DATABASE_URL` كي لا يعتمد على ذاكرة مؤقتة غير متناسقة بين الدوال. لا ترفع `public` وحده؛ تحتاج المستودع كاملاً لنشر الدالة. لا تستخدم خدمة Sites بدلاً من Vercel لهذه الحزمة.

### 6. تغيير اسم المقرر والهوية

- اسم المقرر الصادر عن الخادم في `lib/domain.mjs` في المتغير `course`. غيّر النص الابتدائي المطابق في `public/index.html` أيضاً.
- الشعار في `public/brand.png`. استخدم ملفاً تملكه أو يحق لك استخدامه.
- الألوان والأبعاد في أول `public/style.css`. إذا استبدلت الصورة بشعار مقصوص، عدّل `.brand-window` وموضع الصورة لإظهاره كاملاً.
- أسئلة البداية في `db/schema.sql` لقاعدة جديدة و`lib/domain.mjs` للوضع المؤقت. تغيير ملف البداية لا يغيّر واجباً سبق حفظه؛ أنشئ واجباً جديداً من الواجهة.

## هيكل المشروع

| المسار | الوظيفة |
|---|---|
| `public/index.html` | هيكل الصفحة العربية |
| `public/style.css` | الهوية والتجاوب |
| `public/app.js` | التنقل والنماذج والاتصال بالخادم |
| `public/brand.png` | الصورة الأصلية المرفقة |
| `api/app.js` | قائمة الواجبات والإنشاء والتسليم والملخص |
| `lib/domain.mjs` | القواعد والتحقق والتصحيح |
| `lib/store.mjs` | الحفظ المؤقت أو Neon باستعلامات ذات معاملات |
| `db/schema.sql` | إنشاء الجداول والبيانات التجريبية |
| `server.mjs` | تشغيل محلي دون Vercel CLI |
| `tests/app.test.mjs` | اختبارات الخادم والقواعد |
| `vercel.json` | إعداد النشر وترويسات الأمان |

العلاقة: كل سجل `quizzes` يحتوي أسئلة الواجب في JSONB، ويرتبط بعدة سجلات `attempts` بالمفتاح `quiz_id`. المقرر ثابت في الإعدادات لذلك لا يحتاج جدولاً، ولا يوجد جدول مستخدمين. لا يحذف المشروع المحاولات تلقائياً. واجبات الإنشاء ثابتة بعد النشر لحماية اتساق درجات المحاولات.

## الحدود والتحقق

- 20 سؤالاً للواجب؛ أربعة خيارات؛ 100 حرف للعنوان، 500 للسؤال، 200 للخيار؛ 32 KiB لطلب JSON. حد الطلب قد يمنع واجباً يصل للحد الأقصى في جميع الحقول معاً.
- لا يرسل API مفتاح الإجابات للواجهة. لا يقبل درجة يرسلها الطالب؛ يعيد حسابها في الخادم.
- فحص الدور خادمي، لكن قيمة `x-demo-role` يحددها الزائر؛ لا تعدها حماية.
- لا تُجمع عناوين IP بواسطة التطبيق، لكن قد تحتفظ خدمات الاستضافة بسجلات تشغيل خاصة بها.
- واجهة الواجبات تعرض آخر 100 واجب كحد أقصى لهذه النسخة الصغيرة.
- لا ضمان لمنع تكرار التسليم عند إعادة طلب الشبكة؛ كل طلب ناجح محاولة مستقلة.

## إذا واجهت مشكلة

| المشكلة | الحل |
|---|---|
| `node` أو `npm` غير معروف | ثبّت Node.js 24 وأعد فتح Terminal |
| المنفذ 3000 مشغول | أوقف النسخة المحلية السابقة بـ Ctrl+C |
| الصفحة دون بيانات | افتح عبر `npm run dev` لا عبر ملف HTML مباشرة |
| خطأ اتصال بقاعدة البيانات | راجع DATABASE_URL وتشغيل schema.sql في القاعدة نفسها |
| رسالة DEMO_MODE | أضف `DEMO_MODE=true` وأعد تشغيل الخادم أو النشر |
| اختفاء البيانات محلياً | هذا متوقع في وضع الذاكرة؛ استخدم Neon للاستمرار |
| API غير موجود على Vercel | تحقق من جذر المشروع، الإطار Other، ورفع `api` مع `public` |

## نطاق التحقق قبل التسليم

شغّل `npm test` لاختبارات القواعد وAPI، و`npm run build` لفحص الصياغة والأصول (الواجهة لا تحتاج تجميعاً). اختبارات الذاكرة ليست اختبار تكامل Neon حياً. نجاح النشر الفعلي واتصال Neon يتطلب حساباتك ومتغيرات البيئة ثم اختبار الدورة كاملة.

مراجع إعداد النشر: [دوال Node.js على Vercel](https://vercel.com/docs/functions/runtimes/node-js)، [إعدادات Vercel](https://vercel.com/docs/project-configuration)، [Neon serverless driver](https://neon.com/docs/serverless/serverless-driver).
